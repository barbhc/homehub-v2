Choose a file first, search last

ReorderedParse → ScanTitle matches the CTA
You said“Find the manual has not generated good results so far. This should be the last option with text that it’s a beta. Lead with choosing a file. For paste a link, make sure it’s clear the link has to be of a PDF. The title should match the call to action from the previous screens.”

Order is the ranking. Choosing a file leads and carries the only filled control on the screen. Pasting a link is second. Search is last, labelled Beta, and its one line is the truth rather than a pitch: Often returns the wrong document. Check it before you scan.

Saying that plainly is also the honest version of HH‑107. The gate still applies — when nothing clears the bar we show nothing and offer the manufacturer’s own page — but a feature that has been wrong twice should say so where someone decides whether to use it.

Paste a link says Must end in .pdf — not a web page, which is the mistake that actually happens: people paste the product page.

Scan, not parse. Every screen now says scan — the button here, the header on 04, the progress line. It also avoids the reading you didn’t want: nobody should think the app is opening the manual for them to read.

Tasks appear as they’re found

From C — 03Parse → Scan

Each finding lands with the page it came from, so the wait is filled with evidence instead of a spinner. The counts climb as the scan goes on. A blank stays blank until the manual has actually said something — naming a task we haven’t been told about would be inventing it.

The rows use the app’s real tier rails: clay for essential, teal for recommended, slate for optional. Same vocabulary as the agenda and item detail, so nothing new has to be learned here.

05

Two decisions, big; five things, folded

From C — 04Hierarchy rebuiltReclassify added
You said“Tighten up the design, there’s a lot of small text with no sense of hierarchy. Allow users to see the cleaning tasks and setup tasks and reclassify them here. But keep them hidden unless the user explicitly wants to see them.”

The old version had six different sizes between 10 px and 12.5 px, which is the same as having none. This one has four, and each does one job: the section title at 20, task titles at 16, controls at 16, meta at 12.

Each task is now its own card with room to breathe: title on the tier rail, the how-often control at full width and full height, the reminder as a plain sentence and a switch. Nothing is squeezed into a 56 px label column any more.

The other five are one line, folded. They are already saved and nothing reminds you about them, so the row states that and offers Show. Hidden until asked for, exactly as you said — and the button count stays honest at seven.

A calendar for the date, a memory for the store

New
You said“For the Choose a date, allow a calendar picker. And for Where you bought it, prefill with previously entered stores or sites to normalize entries.”

The date opens a month grid in place rather than a native spinner, because a purchase date is nearly always a month or two back and scrolling three wheels to get there is worse than tapping a number. Typing still works — the field is an input, not a button.

The store suggests as you type, ranked by how often you have used each one, so the second fridge you add offers Home Depot before you finish the word. That is what stops one home accumulating “home depot”, “Home Depot” and “HomeDepot” as three different stores.

The last row always offers exactly what was typed. Suggesting is not the same as deciding, and a store we have never seen has to be enterable without a fight.
